# Homework 05 补充说明：中文文件名的乱码问题

## 现象

上传文件名含中文（或其他非 ASCII 字符）时，文件列表与下载后的文件名显示为乱码，例如显示成类似 `ä¸­æ–‡.txt` 的字符。

## 原因

浏览器通过 `multipart/form-data` 上传文件时，文件名以 UTF-8 编码传输。multer / busboy 在解析请求头中的文件名时，会把这段字节按 `latin1`（ISO-8859-1）解码保存到 `file.originalname`。当后端直接把这个字符串当作磁盘文件名写入时，保存下来的就是"UTF-8 字节被 latin1 误读"后的乱码；随后 `readdirSync` 读出的自然也是乱码。

也就是说：**文件内容没有问题，问题出在文件名在"字节 → 字符串"这一步被错误解码**。

## 修复方式

在后端 `backend/src/file.ts` 的 multer `filename` 回调中，把 `file.originalname` 按相反的编码转换还原：

```ts
filename: (req, file, cb) => {
  // 将 busboy 以 latin1 解码出的字符串还原为 UTF-8
  file.originalname = Buffer.from(file.originalname, "latin1").toString("utf8");
  return cb(null, file.originalname);
}
```

修改后需要重新上传一次文件（旧文件是已落盘的乱码名，不会被自动修复）。上传后用文件列表查看、下载，中文文件名应显示正常。

## 备选方案

如果不想依赖客户端文件名，也可以让后端自己生成安全文件名（如 `uuid` 或"时间戳-随机数"），并把原始文件名单独记录到数据库或额外元数据中。这样磁盘文件名永远与用户输入解耦，能彻底避开编码问题；代价是需要额外的"原名映射"存储。

## 验证方法

1. 上传一个名为 `测试文档.txt` 的文件；
2. 文件列表应显示 `测试文档.txt`；
3. 下载后本地文件名也应为 `测试文档.txt`。
